# YouTube 探测生命周期核对（2026-10-21）

基线：`ae12a10`（2026-09-20，早于 10 月 19 日）；修复前：`f97765d`（1.1.44）。

## 地址解析与自动调度分开核对

旧版完整解析器已能枚举组合流、自适应视频和音轨，不能把自动跳片问题归因于旧解析器。保留完整格式解析、运行时、站点隔离和历史成功率排序，不固定某个默认解析方法。

1.1.44 额外加入的 `--socket-timeout 6`、`--retries 0`、`--extractor-retries 0` 已撤回，恢复旧版网络重试行为。原有每次解析 15 秒上限保持不变。

| 核查项 | 修复前差异 | 本次统一 |
| --- | --- | --- |
| 手动探测 | 同视频正在探测时可能被去重拦截 | 明确强制开始新一轮，取消旧一轮 |
| 自动切片 | 发出 Next 前额外销毁会话 | 只请求播放器切换，由实际网页/播放器变更走公共入口 |
| 重复网页通知 | 探测完成后相同视频可以再次重启 | 同一视频通知去重，显式手动探测和新文档导航除外 |
| URL 与播放器 ID 更新先后 | 旧播放器 ID 可能覆盖新 URL 的视频 ID | URL 有明确视频 ID 时优先采用 URL |
| YouTube 时长变化 | 同视频时长初始化抖动会清空结果并重启 | 明确相同 YouTube ID 时不因时长变化重启 |
| 结果展示 | 事件回调直接更新发现列表 | 当前会话先缓存，公共退出完成清理和封口后统一发布一次 |
| 旧结果 | 同站点兜底可能放过其他视频 | 明确视频 ID 不一致直接拒绝，且旧会话结果无法进入新会话 |
| 自动超时 | 独立的无地址计时可能先于完整探测结束 | 等待公共探测退出，再消费最终成功/失败结果 |

## 保留的解析差异及理由

- 旧版会把上一次获胜方法置顶；当前仍按历史成功率排序，不恢复置顶，遵守用户“不固定默认方法”的要求。
- 旧版按会话条件在外层轮询多个方法；当前以排序后的方法为外层，同一方法内尝试匿名/登录态，避免会话条件改变方法顺序。
- 保留随程序部署的 JavaScript 运行时及解析器更新，不回退可执行依赖。
- 保留完整清晰度、音轨配对、直播判定和视频 ID 归属检查；不将无音轨的视频伪装成音视频组合流。
- 保留未解析出已声明高清时的未完成状态；解析器的中间状态与最终可下载结果不混用。

## 统一调用链

手动“探测”、文档导航、SPA 变更、播放器内容变更和选中标签页均进入 `RestartDetectionForPageChange` → `StartPageDetectionSession` → `RunStableDetectionSessionAsync`。

自动模式仅执行 Next 并等待上述公共流程，不启动自己的解析器。所有结果事件进入 `DetectionResultBuffer`；完成外部解析器取消/清理及 `CompleteDiscoveryAsync` 后，由同一出口发布最终列表。取消、替换和结束后到达的旧结果均不能再次发布。

## 验证范围

自动化回归覆盖：结果只发布一次、取消及替换后的结果隔离、未完成的清晰度不发布、低清晚到不能覆盖高清、YouTube 同 ID 时长抖动不重启、真实新 ID 正常切换，以及原有探测调度、自动下载切换、防重复和方法排序检查。

本次未把命令行解析样例当作客户端多入口连续播放验收；客户端长时间运行稳定性仍需实际使用观察。
