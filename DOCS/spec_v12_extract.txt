1. 产品目标与范围
1.1 产品定位
本软件定位为 Windows 桌面“网页视频探测 + 下载器”。软件内置 WebView2 浏览器，用户在正常浏览、登录和播放网页视频的过程中，程序从浏览器网络层观察实际 HTTP/HTTPS 请求，识别 MP4、HLS（m3u8）和 DASH（mpd）媒体资源，并在保留合法浏览会话所需请求上下文的前提下执行下载。
1.2 核心目标
网页无需提供“下载按钮”，只要浏览器实际请求到非 DRM 媒体资源，软件即可将其识别为候选资源。
支持普通 MP4、HLS、DASH 三类核心媒体。
处理 blob/MSE 场景：不下载 blob URL 本身，而是定位其底层媒体请求。
自动关联 Cookie、Referer、Origin、User-Agent 及必要请求头，降低“浏览器能播放但下载 403”的概率。
支持下载任务持久化、失败重试、暂停/恢复、取消和程序重启后的恢复。
对用户展示“视频”而非大量底层分片请求；同一视频的不同清晰度应归并展示。
首版重点兼容目标：YouTube、Bilibili、抖音、TikTok 与通用网页；重点站点采用独立适配器增强，适配失败时允许降级到通用 WebView2 嗅探链路。
对 DRM 保护内容明确识别并标记为不支持。
1.3 非目标与边界
范围
处理原则
Widevine / PlayReady / FairPlay 等 DRM
识别为 DRM 或受保护流，停止下载链路；不实现密钥提取、许可证绕过或解密。
系统级 HTTPS 抓包
首版不采用 WinDivert/WinPcap/代理 MITM；避免证书注入、QUIC、HTTP/3 等复杂度。
绕过登录/订阅/付费权限

直播录制
不列入首版核心验收；架构保留后续扩展空间。
跨平台
首版仅 Windows。
2. 总体架构
2.1 架构原则
浏览器层探测优先：基于 WebView2 + CDP，不从网卡层做系统抓包。
双探测源：CDP 与 WebResourceResponseReceived 同时作为正式来源，统一归一化并去重。
请求上下文跟随资源：Cookie/Referer/Origin/UA/Headers 属于 MediaResource，不允许使用全局可变下载上下文。
网络资源与用户视频分离：MediaDetector 只识别资源；MediaAggregator 将底层资源归并成用户可理解的视频/清晰度集合。
Core 不依赖具体 UI、WebView2、SQLite 或 FFmpeg；这些放入 Infrastructure。
状态机驱动下载状态，避免 UI、Repository、Downloader 多方直接写状态造成语义冲突。
I/O 全异步，所有长任务支持 CancellationToken。
日志不得输出完整 Cookie、Authorization、签名 Token。
站点逻辑插件化：YouTube、Bilibili、Douyin、TikTok 的规则只存在于独立 ISiteAdapter 实现中，不得写入 MediaDetector、DownloadEngine 或 UI 条件分支。
通用嗅探永远存在：站点适配器是增强层而非唯一入口；适配器失败、规则过期或被禁用时，可回退 Generic Adapter，对浏览器实际产生的 MP4/HLS/DASH/媒体轨继续探测。
下载后端按能力路由：单轨 Direct HTTP、Manifest/多轨 FFmpeg 等通过统一 Backend Router 选择；站点适配器只负责识别、归并和补充元数据，不直接写文件。

4. 核心领域模型
4.1 RequestContext
RequestContext 是本系统最重要的安全与正确性契约之一。资源被确认进入候选媒体时，必须立即对当前 WebView2 会话中与该资源有关的 Cookie、Referer、Origin、User-Agent 和必要 Header 做深度复制，形成不可变快照。下载任务只能使用自己绑定的快照或其受控刷新版本；禁止全局 UpdateContext()、禁止多个任务共享并覆盖可变 Header/Cookie 状态。
public sealed record RequestContext(    Guid ContextId,    int Version,    string? Referer,    string? Origin,    string? UserAgent,    IReadOnlyDictionary<string, string> Headers,    IReadOnlyList<BrowserCookie> Cookies,    DateTimeOffset CapturedAt);
4.1.1 生命周期与受控刷新
初始探测：创建 Version=1 的不可变 RequestContext，并与 MediaResource/MediaVariant 绑定。
下载请求：不得重新从全局 WebView2 状态临时拼接上下文；所有认证相关信息来自任务绑定的 Context。
401/403：允许触发一次受控上下文刷新。刷新必须从当前 WebView2 重新采集并生成 Version+1 的新快照；旧快照保留用于审计/回退，不得原地修改。
刷新后仍失败：按明确错误结束，不允许无限刷新、无限 403 重试。
持久化：非敏感元数据可明文保存；Cookie、Authorization、敏感签名等必须使用 Windows DPAPI（CurrentUser）保护后落盘。

5.3 NetworkEventNormalizer
两个来源产生的事件必须先进入 NetworkEventNormalizer，再送 MediaDetector。CDP requestId 仅作为 CDP 内部 requestWillBeSent/responseReceived 关联主键，不作为跨来源唯一主键。WebResourceResponseReceived 无 CDP requestId 时，跨来源去重采用“规范化 URL + Method + FrameId（可用时）+ Range/Content-Range + 状态码/响应特征 + 有界时间窗口”的组合指纹。Normalizer 同时负责 Header 大小写统一、URL 规范化、请求/响应合并和时间戳记录。
public interface INetworkEventNormalizer{    ValueTask<NormalizedNetworkEvent?> NormalizeAsync(        RawNetworkEvent input,        CancellationToken cancellationToken);}
5.3.1 事件通道、背压与缓存边界
WebView2/CDP 回调只提取最小必要字段并立即写入有界 Channel<RawNetworkEvent>；禁止在每个事件回调中 Task.Run 执行完整解析。
Channel 必须配置容量上限和明确的满载策略。媒体主请求、Manifest 和响应头事件不得静默丢弃；低价值重复分片事件允许在压力下优先降级。
去重缓存必须同时设置“最大条目数 + TTL”，二者任一达到即淘汰；不得仅依靠固定 500 条而无时间淘汰。默认值由配置给出并通过压力测试确定。
后台单消费者或有限并发消费者执行 Normalize -> Detect -> Aggregate，确保事件乱序可控、内存不会因事件洪峰无限增长。

6. 媒体识别与归并设计
6.1 MediaDetector 职责
MediaDetector 只回答“这个网络资源像什么”，不负责决定用户界面最终显示几条视频。Detector 应返回类型、置信度和识别原因。
public interface IMediaDetector{    MediaCandidate? Detect(MediaResource resource);}

6.3 MediaAggregator 职责
MediaAggregator 将 MediaCandidate 归并成 DetectedVideo。用户看到的应是“某视频 - 1080p/720p/480p”，而不是 master.m3u8、多个子 playlist、几千个 ts/m4s 分片。
HLS：优先以 master playlist 为根，variant playlist 为清晰度。
DASH：以 MPD 为根，Representation 组合成清晰度与音轨。
Direct MP4：相同 PageUrl、相近时间、URL 仅 token 差异的资源可做弱归并，但不得误合并。
广告过滤：只做启发式，不以域名黑名单作为唯一依据。
一旦识别 DRM，DetectedVideo 标记 IsDrmProtected=true 并禁止进入下载。
6.4 站点适配架构
站点适配层用于提高重点平台的标题识别、内容 ID 识别、音视频轨配对、短时效 URL 处理和错误诊断成功率。它不替代通用网络嗅探，也不得拥有绕过 DRM、登录、订阅、付费、验证码或地区限制的能力。
public interface ISiteAdapter{    string SiteId { get; }    int Priority { get; }    bool CanHandle(Uri pageUrl);    Task<SiteProbeResult> ProbeAsync(        SiteProbeContext context,        CancellationToken ct);}public sealed record SiteProbeContext(    Uri PageUrl,    string? PageTitle,    IReadOnlyList<MediaCandidate> GenericCandidates,    IReadOnlyList<NormalizedNetworkEvent> RecentNetworkEvents);public sealed record SiteProbeResult(    SiteProbeStatus Status,    string SiteId,    IReadOnlyList<DetectedVideo> Videos,    bool AllowGenericFallback,    string? ErrorCode);
适配器执行规则：
Router 依据 PageUrl 选择最高优先级匹配适配器；无匹配时直接使用 GenericAdapter。
通用 Detector/Aggregator 始终运行。站点适配器可以合并、补充或修正 GenericCandidates，但不得吞掉原始候选而不给回退路径。
适配器返回 Success 时，以 SiteId + SiteContentId + Track 特征与 Generic 结果去重；返回 RecoverableFailure/空结果且 AllowGenericFallback=true 时继续 Generic。
站点签名 URL、Cookie、Context 仅作为短时效资源处理；403/410 可触发一次受控重新探测（re-probe），不得无限刷新或高频重试。
可选 yt-dlp 外部解析器必须封装在 Infrastructure/ExternalResolvers；其输出必须转换为统一 DetectedVideo/MediaVariant/MediaTrack，不得让 yt-dlp 数据模型泄漏到 Core/UI。
适配器可独立 Feature Flag 禁用。单一站点规则失效时，不得影响应用启动、Generic 网站或其他站点适配器。

7. HLS / DASH Manifest 解析
7.1 HLS
HLS Resolver 必须支持 master playlist 与 media playlist。首版重点解析 EXT-X-STREAM-INF 中的 BANDWIDTH、RESOLUTION、CODECS 与 URI；相对 URI 必须基于 manifest URL 正确解析。EXT-X-KEY 的 METHOD=AES-128 或 SAMPLE-AES 本身只是加密信号，不能单凭 METHOD 直接判定为 DRM；必须结合 KEYFORMAT、Key URI/许可证交互、浏览器 EME/DRM 信号等进一步分类。标准 HLS AES-128 且 Key 可在用户既有合法会话中按标准方式获取时，可交由受支持的媒体处理链路处理；涉及 Widevine/PlayReady/FairPlay 等许可证体系时必须阻断。
public interface IManifestResolver{    Task<IReadOnlyList<MediaVariant>> ResolveHlsAsync(        MediaResource manifest,        CancellationToken ct);    Task<IReadOnlyList<MediaVariant>> ResolveDashAsync(        MediaResource manifest,        CancellationToken ct);}
7.2 DASH
解析 MPD 根属性、Period、AdaptationSet、Representation。
正确处理 BaseURL 层级继承。
识别视频轨、音频轨及语言。
首版可优先交给 FFmpeg 完成真实分片拉取与音视频合并，但 UI 仍要解析并展示可选 Representation。
发现 ContentProtection / 明确 DRM 标识时阻断下载。
7.3 DRM / 加密内容判定规则
DASH：发现 ContentProtection 时解析 schemeIdUri/value；Widevine、PlayReady 等明确 DRM Scheme 直接标记 DRM_PROTECTED。
HLS：EXT-X-KEY METHOD=AES-128/SAMPLE-AES 不得单独作为 DRM 结论；结合 KEYFORMAT、许可证端点、EME 信号和 Key 获取方式综合判断。
一旦确认需要 DRM License/CDM 才能解密，DetectedVideo.IsDrmProtected=true，UI 不创建可执行下载操作，DownloadEngine 拒绝接收任务。
不得实现许可证提取、CDM 调用绕过、密钥导出或 DRM 解密逻辑。

8.3 断点续传
下载到 <target>.part。
任务持久化 DownloadedBytes。
恢复时不以 HEAD/Accept-Ranges 作为硬前置条件。若本地存在 .part 且 offset>0，直接发送 GET + Range；若保存有强 ETag 或 Last-Modified，则同时使用 If-Range 约束实体一致性。HEAD 仅可作为优化性预探测。
收到 206 Partial Content 后必须校验 Content-Range 起点等于本地 offset；ETag/Last-Modified 与保存快照冲突，或 Content-Range 不匹配时，返回 RANGE_MISMATCH，放弃旧 .part 并从 0 重建。
offset>0 时若服务端返回 200 OK，视为 Range 未生效或实体发生变化：必须截断 .part 并从响应正文 0 开始写入，绝不追加。
收到 416 Range Not Satisfiable 时，根据 Content-Range */total 与本地 .part 长度判断：若长度已等于 total，可进入完整性校验；否则视为断点无效并从 0 重建。完成后校验总长度/可用校验信息，再原子改名。

9. FFmpeg 集成
9.1 原则
FFmpeg 封装在 Infrastructure，不允许 UI 直接 Process.Start。
优先 remux（-c copy），不重新编码。
参数必须使用 ArgumentList 或安全转义，不拼接未经处理的用户文本形成命令行。
日志记录命令模板与非敏感参数；Header/Cookie 必须脱敏。
进程退出码、stderr 尾部摘要和输出文件存在性共同决定成功。
FFmpeg 为控制台进程，不依赖 CloseMainWindow。取消时应启用 StandardInput，优先向 FFmpeg stdin 发送正常退出指令（如 q）并等待短暂宽限期；仍未退出时调用 Kill(entireProcessTree:true)，随后等待主进程结束并清理临时文件/文件锁。
9.2 Header 传递
HLS/DASH 的 FFmpeg 输入必须能够携带资源自己的 RequestContext，例如 User-Agent、Referer、Cookie 与必要 Header。实现层应生成最小必要 Header 集合，不应把浏览器所有敏感 Header 无差别复制。
9.3 进程与日志安全
使用 ProcessStartInfo.ArgumentList 逐参数构造命令；禁止将 URL、文件名或 Header 拼成未转义的整段命令字符串。
RedirectStandardError=true，并持续异步消费 stderr，避免管道阻塞；内存只保留固定大小环形尾部（建议最终诊断摘要 <= 2000 字符）。
FFmpeg 命令和 stderr 在进入日志前必须经过统一 SanitizedLogger；-headers 中 Cookie/Authorization/token/signature 等不得明文记录。
取消/失败后校验 FFmpeg 主进程和子进程已退出；未完成的临时输出不得被标记为 Completed。

卸载程序应让用户选择是否删除浏览器数据、下载历史和日志。

14. 开发计划与里程碑
计划采用 5 个两周 Sprint，共 10 周形成首个 Beta。推荐配置为 2-3 名开发 + 1 名测试：Sprint 1-3 完成通用探测/下载主链，Sprint 4 集中完成 YouTube/Bilibili/抖音/TikTok 站点适配，Sprint 5 完成稳定性、安全、真实站点兼容回归与发布。若单人开发，里程碑顺序不变，工期按实际产能调整。每周末必须进行一次可运行版本演示和风险复盘，Sprint 验收以本文第 16 章为准，不以“代码完成”代替可验收交付。

15.3 CI 自动化最低要求
dotnet format --verify-no-changes -> Release build -> unit tests -> integration tests（启动 TestMediaServer）-> coverage -> package。
核心逻辑覆盖率目标 >= 80%；覆盖率不得通过排除核心业务文件人为达标。
集成测试必须包含 T02/T03/T13/T14/T16/T18/T19；FFmpeg 使用 <10 MB 本地样本，避免依赖公网。
WPF E2E 首版允许以人工冒烟为主；自动化 UI 测试作为 Beta 后增强项，不阻塞 Sprint 1。
15.4 重点站点兼容性回归
站点兼容性测试不依赖固定公网视频永久存在。测试负责人维护一组“当前可公开访问、非 DRM、体积适中”的 RC 测试 URL，并记录测试日期与内容 ID。
PR/普通 CI 主要使用本地 fixture、录制后的脱敏响应和 TestMediaServer；真实 YouTube/Bilibili/Douyin/TikTok 回归至少在每个 Release Candidate 执行一次。
重点站点任何一个 Beta 必验用例失败，必须区分 Core 回归、Adapter 失效、平台临时故障/地区限制；不得以“网站变化”为理由跳过诊断。
公开站点测试必须遵循正常访问频率；不得通过自动验证码绕过、指纹规避、高频重试等方式制造通过结果。
16. 验收标准
16.1 总体验收门槛
所有 P0/P1 验收用例通过；不存在会产生损坏文件、任务状态错乱或泄露敏感 Header 的已知缺陷。
程序在 Windows 10/11 x64 上可安装、启动、卸载；首次启动无额外开发环境依赖。
核心单元测试覆盖率 >= 80%；CI 构建和自动测试全绿。
WebView2 页面可正常导航、登录，关闭/重开应用后用户数据目录行为符合设计。
普通 MP4、HLS、DASH 三类非 DRM TestMediaServer 测试源均可完成端到端流程；同时通过 YouTube、Bilibili、抖音、TikTok 与通用网站的 v1.2 Beta 兼容矩阵。
DRM 测试源必须明确阻断，不允许误报为可下载。
下载任务异常退出后可恢复，不允许将未完成任务误标 Completed。
日志经过抽查，不得出现完整 Cookie、Authorization 或敏感签名参数。

16.7 性能基准
指标
首版验收目标
空闲内存
应用稳定后建议 < 350 MB（不含外部 FFmpeg 峰值）；WebView2 页面复杂度会影响结果
探测延迟
测试服务器媒体响应出现后 2 秒内出现在发现列表
UI 响应
下载过程中 UI 操作无明显卡死；主线程不得执行网络/文件大 I/O
下载吞吐
单流下载不应无故低于同机 curl/浏览器直连吞吐的 80%（排除服务端限速）
任务规模
至少稳定保存 1000 条历史任务，列表分页/虚拟化后可用
事件缓存
Channel 和去重缓存均必须有界；达到上限时按定义的背压/降级策略处理，不允许无限增长
敏感数据
日志与 SQLite 明文区域对测试 Cookie/Authorization/token 的检出数必须为 0
17. 发布与部署
17.1 发布包
Windows x64 安装包（MSIX/WiX/Inno Setup 三选一，团队统一）。
明确 WebView2 Runtime 依赖策略：Evergreen Runtime 检测/引导。
FFmpeg 采用“用户指定路径”或“随包分发”二选一；随包分发时完成相应许可证合规材料。
yt-dlp 若作为可选 ExternalResolver 随包分发，必须固定版本、提供版本/许可证清单和升级策略；若不随包分发，缺失时不得阻塞应用启动。
应用数据默认写入 %LOCALAPPDATA%\VideoDownloader；用户下载目录单独配置。
版本号采用 SemVer，例如 1.0.0-beta.1。
17.2 CI/CD 最低要求
restore -> build Release -> unit tests -> integration tests        -> package -> smoke test -> artifact publish
主分支必须受保护；合并前构建与测试通过。Beta 发布应附 CHANGELOG、已知问题和安装说明。

附录 C：关键标准与官方实现参考
HTTP Range：RFC 9110《HTTP Semantics》，重点关注 Range、Accept-Ranges、Content-Range、If-Range、206 与 416 语义。Accept-Ranges 仅为能力提示，不是客户端发送 Range 的硬前置。
HLS：RFC 8216《HTTP Live Streaming》，EXT-X-KEY 定义 NONE、AES-128、SAMPLE-AES；实现不得仅依据 METHOD 判断 DRM。
WebView2：Microsoft WebView2 CoreWebView2.WebResourceResponseReceived 与 CDP 文档；WebResourceResponseReceived 用于观察已实际发送的请求/收到的响应，跨来源仍需自行归一化去重。
.NET HTTP：Microsoft Learn《Use the IHttpClientFactory》及故障排查文档明确提示 CookieContainer 可能随 Handler 池共享；本项目因此采用请求级 Cookie、UseCookies=false。
.NET Process：Process.CloseMainWindow 仅适用于有图形主窗口的进程；FFmpeg 取消使用 stdin 正常退出 + 超时 Kill(entireProcessTree:true)。
Windows DPAPI：System.Security.Cryptography.ProtectedData，仅 Windows 支持；本项目使用 CurrentUser 保护需跨重启保存的敏感 RequestContext 字段。
站点兼容参考：yt-dlp 官方 Supported sites/Extractors 用于评估站点解析变化；其存在不构成产品兼容保证。YouTube 等站点会持续调整 JS challenge/访问策略，发布验收必须以当前真实测试为准。
参考项目（仅作为实现/回归研究）：yt-dlp（站点 Extractor 与 Generic fallback）、N_m3u8DL-RE（HLS/DASH 下载实现参考）。第三方代码是否直接复用须单独做许可证和集成评审。
